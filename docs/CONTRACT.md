# Internal API contract

All responses are JSON; errors use `{error: string}`. Default daemon is `127.0.0.1:47821`. UI dev server is `127.0.0.1:47822` and proxies `/api/*` to daemon `/*`, `/stream` to daemon WS. Production daemon serves dashboard `apps/dashboard/dist` and supports `/api` prefix as alias.

Optional public mode requires `BLACKBOX_PUBLIC_ORIGIN` (HTTPS) and `BLACKBOX_ACCESS_TOKEN` (at least 32 characters). It accepts a bearer token on HTTP and WebSocket requests or the secure browser session cookie set by `POST /login`; `GET /login` serves the form. The login form accepts navigations from other origins because the access key itself is required, but API and WebSocket requests still reject other origins; all routes check the Host header. Local mode needs no key and remains loopback-only. Successful durable mutations in Azure SQL snapshot mode wait for a checkpoint; unavailable storage returns 503. Application heartbeat updates are soft state and do not wait for a checkpoint.

- `POST /events`: full protocol event or array, validated atomically; returns `{events: StoredEvent[]}`. Event IDs deduplicate. `GET /events` query fields from EventQuery returns QueryResult newest first. Default `order=sequence` sorts recorded order; the dashboard uses `order=timestamp` for chronological event time. `before`/`after` are sequence IDs; in timestamp mode they identify the timestamp/sequence tuple anchor (expired/unknown anchors return 400). Replay and export always use ascending recorded sequence. `GET /events/:id` returns `{event}`. `GET /events/:id/context` returns EventContext.
- `GET /projects` -> `{projects: ProjectRecord[]}`. `POST /projects` accepts ProjectRecord -> `{project}`. `GET /projects/:id` -> `{project,events,stats}` where stats contains status, runningProcesses, ports, lastCommand, lastDeployment, environmentWarnings, errorsToday, connectedTools.
- `GET /sources` or `/applications` -> `{applications: ApplicationRecord[]}`. `POST /applications` registration -> `{application}`. `POST /applications/:id/heartbeat` with `{health?}` -> `{application}`.
- `POST /capabilities` `{appId,capability}` -> `{capability}`. `POST /actions` `{appId,action}` -> `{action}`.
- `POST /commands` CommandInput -> `{command: CommandRecord}` (202). `GET /commands/:id` -> `{command}`. Provider `POST /commands/:id/ack` `{appId,status:'accepted'|'completed'|'failed',result?,error?}`. Command delivery is only to live WS registered provider. No shell execution in daemon. Confirmation-required capabilities require `confirmed:true`; UI asks user explicitly. Timeout persisted. Ambiguous providers rejected.
- `WS /stream?patterns=process.*,deploy.*&appId=pit-boss&since=0` emits StreamMessage union. App ID optional; connects subscriptions and provider commands. `since` replays ascending sequence; replay must not re-execute commands. On open ready message. Reconnect resumes from last sequence.
- `POST /logs` `{source:{app,version?},project?,stream:'stdout'|'stderr'|'file',lines:string|string[],correlationId?}` -> `{events}`. Text and JSON lines normalized and redacted.
- `GET /incidents` -> `{incidents}`. `POST /incidents` `{eventId,title?}` -> `{incident}` using correlated context. `PATCH /incidents/:id` `{status:'open'|'resolved'}` -> `{incident}`.
- `GET /health` -> `{status:'ok',version,uptime,eventCount,latestSequence,remoteSync:false}`. `GET /settings` -> `{retention:RetentionPolicy}`. `PATCH /settings` `{retention}`. `POST /maintenance` -> `{deleted}`. `GET /export` query filters -> newline-delimited JSON attachment (redacted). `GET /ecosystem` -> health summary for Shipwreck (no raw logs). Optional remote integrations remain off.

Schema/type source: `packages/protocol/src/index.ts`. All agent-owned code may import protocol via alias. Root owns package installation and build configuration.
